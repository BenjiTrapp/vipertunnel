      payload tap
      
    0
    
    pcap (reconstructed)
  
      
  
      The bytes the relay actually carried, newest session first.
    Bounded: the first 4 KiB and last 1 KiB of each direction, of the last
    eight sessions, in memory only. Never written to the ledger — that file
    is the one a finding cites and it stays quotable.
      
  
      The pcap's framing is reconstructed, not captured. Real:
    the bytes, their order, their chunk boundaries, the time this server
    relayed each one, and the four-tuple — the implant's own source address
    comes back in the dialect's reply. Invented: the IP and TCP headers, the
    sequence numbers, and a handshake at the front so it opens as a
    conversation.
      
  
      

      


      
  Every value here comes from events that went to the ledger file as well;
  the file stays the artefact a finding cites. The cadence is the mean,
  standard deviation and coefficient of variation over the gaps between
  client-connected events from one host — the arithmetic a
  beaconing detection runs. A listening HTTP port is a trait this family does
  not have, so this binds loopback only: reach it over an SSH forward.
